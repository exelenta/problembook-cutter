# Problembook Cutter

원서 PDF의 문제를 **원본 영역 그대로 잘라 붙여** 풀이 공간이 있는 A4 문제집을 만드는 웹앱입니다. 수식·문장을 옮겨 쓰지 않습니다. 원본 PDF와 출력은 브라우저에서 처리합니다. 연습문제 범위 자동 검색을 사용할 때만 페이지별 발췌 텍스트를 OpenAI API로 보냅니다.

## 사용 방법

1. 원본 PDF를 열고 `4.1, 4.2, 4.3, 4.4 연습문제 전부`처럼 자연어로 요청합니다. 브라우저가 먼저 무료 로컬 검색으로 관련 페이지를 좁히고, AI에는 최대 40개 후보 페이지만 보내 범위를 판정합니다. 목차 유무와 관계없이 문제 번호의 연속성과 이웃 절을 보고 여러 PDF 구간을 제안합니다. 직접 지정하려면 `23-26, 29-30`처럼 입력합니다.
2. **선택 구간 경계 찾기**를 누릅니다. 공통 지시문은 주황색, 문제는 파란색 영역으로 표시됩니다.
3. 본문 좌우·위아래와 1단·2단 구간 가이드를 확인합니다. 한 페이지 안에서 T자 또는 역 T자처럼 단 수가 바뀌는 경우도 구간별로 표시됩니다. 같은 페이지에 다른 절이 있으면 가이드 범위를 좁히고 **이 페이지 다시 분석**을 누릅니다. 재분석은 해당 페이지의 기존 편집을 교체합니다.
4. 모서리를 드래그하거나 좌표를 입력해 경계를 수정합니다. **가로 분할**, **영역 추가**, **이전 문제와 연결**, **이 문제에 조각 추가**로 복잡한 배치를 수정합니다. 다른 페이지에서도 같은 문제에 조각을 추가할 수 있습니다.
5. **현재 페이지 누락 영역 찾기**로 어떤 블록에도 포함되지 않은 잉크를 확인합니다. 선택 해제한 블록도 의도적으로 제외한 것으로 계산합니다. 본문 가이드 밖은 검사하지 않으므로 가이드도 확인합니다.
6. 페이지 전체를 원본과 대조한 뒤 **페이지 검토 완료**를 한 번 누릅니다. 그 페이지의 선택 영역을 함께 검사하며, 잉크를 가르는 경계는 확인 및 출력을 차단합니다. 필요 없는 문제·지시문은 선택 해제합니다.
7. 출력 탭에서 1/2단, 풀이 여백, 풀이 줄, 공통 지시문 반복을 설정하고 PDF를 생성·저장합니다.
8. **프로젝트 저장**으로 JSON을 저장합니다. 나중에 **동일한 원본 PDF를 먼저 열고** 프로젝트를 불러옵니다. 원본 SHA-256 지문을 비교하므로 다른 PDF에는 잘못 적용되지 않습니다.

첫 화면의 연습용 PDF는 직접 만든 합성 문서로, 단 및 페이지를 넘는 연결과 나란한 문제를 연습할 수 있습니다. 사용자가 제공한 교재·예시 문제집은 저장소에 포함하지 않습니다.

## 실행

Node.js 22.13 이상 및 pnpm이 필요합니다.

```sh
pnpm install
pnpm dev
```

개발 서버가 표시하는 주소를 브라우저에서 엽니다. 최신 Chromium 계열 브라우저에서 사용할 수 있습니다. 내장 PDF 미리보기를 지원하지 않는 브라우저는 생성 후 PDF 저장을 이용합니다.

```sh
pnpm typecheck
pnpm test
pnpm build
```

`dist/client`가 정적 프런트엔드 결과입니다. AI 범위 검색은 Vercel의 `api/locate-sections.ts` 함수가 담당하며 Vercel 프로젝트에 `OPENAI_API_KEY`를 설정해야 합니다. 모델은 기본적으로 `gpt-5.4-mini`를 사용하고 `OPENAI_MODEL`로 바꿀 수 있습니다. 서버에서도 후보를 48페이지, 페이지당 1,400자로 제한해 예상 밖의 대용량 API 호출을 막습니다.

## 경계 검출과 출력

- PDF.js로 원본을 144 dpi로 렌더링합니다. 텍스트 레이어는 문제 번호·공통 지시문 위치만 찾는 단서입니다. OCR·수식 인식은 하지 않습니다.
- 본문의 수직 투영에서 중앙 여백을 찾고, 실제로 중앙 단 경계를 충분히 가로지르는 전체 폭 텍스트만 레이아웃 전환 근거로 사용합니다. 얇은 가로 구분선이나 중앙을 조금 넘는 수식은 별도 영역으로 만들지 않습니다.
- 연습문제 머리말 앞의 이전 개념과 다음 절의 큰 번호·제목 또는 구분선 뒤 개념은 자동 분석 범위에서 제외합니다. 문제 번호 뒤에 이어지는 `In Problem ...` 문장은 별도 공통 지시문으로 만들지 않습니다.
- 같은 행의 여러 문제는 해당 구간의 수직 여백으로 분리합니다. 조각 범위의 모든 잉크를 포함하는 사각형과 여유분을 보존합니다.
- `Discussion Problems`, `Computer Lab Assignments`처럼 PDF 내부에서 여러 텍스트 조각으로 저장된 소제목도 앞 문제와 분리합니다.
- 다음 단·페이지 맨 위의 번호 없는 조각은 다음 문제 번호와 공통 지시문의 번호 범위를 함께 비교해 알맞은 이전 문제나 지시문에 임시 연결합니다.
- 번호 누락·중복, 경계 양쪽의 잉크, 편집 후 미포함 영역을 각각 검사합니다. 번호가 다시 작아지는 단원 경계마다 새로 검사하므로 여러 단원에서 반복되는 번호는 중복으로 경고하지 않습니다.
- PDF-lib의 원본 페이지 영역 임베딩으로 벡터·글꼴·수식을 보존합니다. 회전 페이지는 표시 좌표 기준 300 dpi 이미지로 붙입니다.
- 공통 지시문은 범위 내 첫 선택 문제에 붙이며, 옵션으로 각 문제마다 반복합니다. 문제와 지시문, 이어지는 조각은 하나의 배치 단위여서 출력 페이지/단 경계에서 나뉘지 않습니다.
- 긴 문제는 먼저 풀이 여백을 줄이고 필요하면 전체를 축소합니다. 읽기 어려울 정도면 오류로 알려 1단 출력이나 영역 조정을 유도합니다.

## 범위와 한계

**자동 검출은 검토할 초안입니다. 모든 교재에서 완전 자동·무누락을 보장하지 않습니다.** AI 범위 검색은 정확히 일치하지 않는 한글·영문 요청과 여러 절을 처리하지만, 텍스트 레이어가 없는 이미지 전용 PDF에는 OCR이 필요합니다. 저화질·기울어진 스캔, 3단 이상, 겹치는 도형, 불규칙한 번호, 각주·해설 혼합은 직접 편집이 필요합니다.

기본 본문 범위는 머리말·꼬리말을 피하기 위한 추정값입니다. 잉크 검사만으로 모든 문장이 올바른 문제에 속한다는 의미까지 보장하지 않습니다. 원본 대조가 필요한 이유입니다. 매우 옅은 선·잡음은 잉크 임계값에 영향을 받습니다. 처음/마지막 문제의 누락도 원본에서 확인해야 합니다.

파일 제한은 300 MB, 한 번의 분석은 100페이지입니다. 렌더링 캐시는 6페이지로 제한하지만 원본 자체의 메모리는 필요합니다. 큰 책은 장 단위로 나누면 빠릅니다. 편집 상태는 자동 클라우드 저장되지 않습니다.

## 검증

`pnpm test`는 합성 PDF로 번호, 단/페이지 이어짐, 잉크 경계, 누락 영역 검사, 원자적 출력 배치, PDF 재열기·렌더링을 확인합니다. 결과는 Git에서 제외한 `test-output/`에 생성됩니다.

제공된 4페이지 예시의 회귀 검증:

```sh
pnpm test:sample "경로/Differential_Equation_11e_p23-p26.pdf"
```

이 검증은 예시의 기대 번호 1~64, 누락·중복 없음, 54번의 문제 유형 유지, 첫 페이지의 이전 개념과 마지막 페이지의 다음 절 제외, 혼합 단 구간, 단을 넘는 공통 지시문, 모든 분석 범위 잉크의 보관 여부를 검사합니다. 실제 여러 교재의 모든 레이아웃을 검증했다는 뜻은 아닙니다.

실제 교재의 지정 페이지만 오버레이로 검사하고 기대 범위를 자동 검증할 수도 있습니다.

```sh
pnpm inspect:pages "경로/Differential_Equation_11e.pdf" "141-142,145-146,151-153,161-163" --verify
```

브라우저의 클릭/드래그 자동화 검증은 수행하지 않았습니다. 타입 검사, 정적 빌드, HTTP 응답, 실제 PDF의 검출·출력 렌더링으로 검증했습니다. WebMCP 지원 환경에서는 편집 상태 읽기 도구를 등록합니다. 지원 컨텍스트가 없어 WebMCP 호출 검증은 하지 않았습니다.

## 구조

| 파일                         | 역할                                   |
| ---------------------------- | -------------------------------------- |
| `app/page.tsx`               | 업로드·검색·검토·프로젝트·출력 상태    |
| `components/crop-editor.tsx` | 원본 위 SVG 영역 편집                  |
| `lib/detect.ts`              | 잉크 투영, 앵커, 분할, 연결, 누락 검사 |
| `lib/pdf-client.ts`          | PDF.js 렌더링                          |
| `lib/export.ts`              | 원본 조각 임베딩과 분할 없는 배치      |
| `lib/project.ts`             | 저장 형식·원본 지문·좌표 검증          |
| `lib/section-ranges.ts`      | 다중 PDF 페이지 구간 파싱·검증         |
| `lib/ai-section-search.ts`   | 유료 AI 호출 전 로컬 후보 페이지 선별  |
| `api/locate-sections.ts`     | OpenAI 기반 연습문제 범위 추론          |
| `scripts/verify.ts`          | 합성·실제 예시 회귀 검사               |

의존성은 각 프로젝트의 라이선스를 따릅니다. PDF.js의 글꼴·CMap·WASM은 실행/빌드 시 패키지에서 복사됩니다.
